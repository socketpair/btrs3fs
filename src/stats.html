Zones

One cell per zone in disk order, left to right; partly written zones fill from the bottom. Hover a cell for a summary, click it for what the zone holds — below the map; the switch above dims all zones but data or metadata ones. “Upload buffered data” stores everything held in RAM now but does not commit btrfs. “Concatenate fragmented zones” merges the S3 objects of every zone that has more than one. “Commit the filesystem” is syncfs(): btrfs writes its transaction, so every written file is stored in S3. “Remove empty block groups” is btrfs balance start -dusage=0 -musage=0 (data, metadata and system): their zones are reset and their S3 objects deleted. The daemon runs the same by itself, at most once a minute, when btrfs freed space and an empty block group still holds a zone stored in S3; “Pause automatic removal” stops that until resumed.

Each value is auto — the daemon estimates it from its own S3 traffic and adapts as the link changes — or manual. Tick “manual” to set one; Enter applies it. The auto column stays visible either way. Settings made here last until the daemon restarts; to keep them, save the file below and pass it as mount --link-config.

Measurement

Waits for the S3 requests in flight, holds new ones back, then measures for at most 20 s and lets them go: reads of the disk's own objects (zones stored in one object), writes of temporary objects that are deleted afterwards (no writes on a read-only disk). Writes wait in RAM meanwhile, reads wait.
