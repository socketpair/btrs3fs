# btrs3fs — план и статус

Решения и устройство — `SPEC.md`, пользовательское — `manual.md`; здесь — что сделано и что
осталось. После каждого этапа — коммит и отметка здесь.

## Код

```
src/
  main.rs       CLI (clap): create / mount / umount / run / detach / destroy; fork демона
  config.rs     disk.json (DiskConfig, проверки), creds.json; все константы с обоснованием
  store.rs      Store: S3 или MemStore (тесты, run --memory); раскладка ключей
  s3.rs         S3Store: reqwest (HTTP/1.1) + aws-sigv4 + quick-xml, повторы, DeleteObjects, теги
  zones.rs      движок зон: состояния, буферы, выгрузка, FINISH/RESET, фоновая выгрузка,
                восстановление; без ublk, покрыт юнит-тестами на MemStore
  readahead.rs  окна чтения с запасом и их LRU
  device.rs     ublk: параметры, очереди, разбор команд, мост в tokio через eventfd, sysfs
  stats.rs      счётчики и веб-страница (stats.html)
  logging.rs    journald / syslog / stderr
```

Тесты: `cargo test` (юнит), `BTRS3FS_CREDS=creds.json cargo test -- --ignored` (против
бакета, префикс `test/`). Каждый этап проверяется и на реальном устройстве.

## Сделано

- [x] **Движок и устройство.** Зоны в RAM, ublk (`USER_COPY | ZONED`, 4K-блок, кеш записи +
      FUA), `run --memory`; `blkzone`, `fio` zbd с verify, `mkfs.btrfs -O zoned` — без ошибок.
- [x] **S3.** SigV4, PUT/PATCH/GET/DELETE/List, повторы; `create`/`destroy`; восстановление
      зон из List; лимит грязных данных; остановка без досылки несброшенного.
- [x] **Сохранность.** Диск 10 ГиБ: 227 файлов → umount → detach → run → mount — все sha256
      совпали; `fio` verify после перезапуска; обрыв S3 через прокси — `EIO` на fsync,
      данные в RAM, досылка после восстановления.
- [x] **Монтирование и логи.** `mount` (fork, готовность по pipe), `umount`, journald,
      systemd unit (`Type=notify`), README.
- [x] **Аварии.** Смерть демона — `FAIL_IO` (флаг принят в `libublk` апстрим,
      §9.4): ФС отключается, `umount` проходит, сброшенное цело; разбор зависаний ядра —
      `bugreports/`.
- [x] **Статистика.** Веб-страница `127.0.0.1:9470+N`, `/stats.json`.
- [x] **FINISH и лимиты зон.** Тег `btrs3fs-zone=finished`; лимитов open/active нет (малый
      лимит вешает btrfs); после перемонтирования 23 закрытые FINISH зоны — FULL, sha256 совпали.
- [x] **Меньше запросов к S3.** `io_opt` = зона (дозаписи крупные, файлы одним экстентом);
      фоновая выгрузка до 16 зон, FULL первыми; `DeleteObjects` в `RESET_ALL`/`destroy`.
- [x] **Чтение.** Окно 256 КиБ + LRU 64 МиБ (холодный `cat` 9 тыс. файлов: 5354 → 498 GET);
      только HTTP/1.1; wbt выключен; запрос ядра 512 КиБ (большие файлы ≈9,5–12 вместо 4–6 МиБ/с).
- [x] **Подстройка под связь с S3.** `btrs3fs measure` + флаги `--s3-*`; окно чтения, запрос
      ядра, упреждение btrfs (выставляется после монтирования) и число выгрузок выводятся из
      них. На ВМ в облаке: крупное чтение 91–107 вместо 31–47 МиБ/с, мелкие файлы 8–12 вместо
      22–24 с, запись 128–163 вместо 88–122 МиБ/с (`SPEC.md` §6.1, §12).
- [x] **Перенос экспериментов на ВМ** в Yandex Cloud (`tools/deploy-vm.sh`).
- [x] **S3 без дозаписи.** `create` определяет `PATCH` / `PUT_APPEND` / `SEGMENTS`; метка FINISH —
      объект `<зона>.finished`; `DeleteObjects` с CRC32C. `SEGMENTS`: фрагмент на выгрузку, фоновая
      склейка на сервере с проверкой поколения против гонки с RESET. Selectel: 200 файлов с `fsync`
      — 152 мс на файл, sha256 после перемонтирования совпали (`SPEC.md` §5, §11, §12).
- [ ] **Аварийные тесты** — внезапная остановка демона посреди разных операций, параллельная
      нагрузка, гонки (запрос пользователя 2026-10-26).
- [x] **Диагностика.** Трассировка запросов (`requests=trace`); проверено, что btrfs помечает
      метаданные `REQ_META` (`SPEC.md` §11).
